# 도메인 용어 정리

이 시스템을 처음 맡는 사람이 **코드를 읽기 전에** 먼저 읽어야 하는 문서입니다.
용어를 모르면 코드의 조건문이 왜 그렇게 생겼는지 알 수 없습니다.

---

## 이 시스템이 하는 일 (한 문단)

아파트 등 현장에 도어록·홈네트워크 장비를 설치한 **설치점**이, 공사가 끝나면
장비를 발주처로 넘기기 위해 **이관검사**를 신청합니다. **감독관**이 서류를 검토하고
현장을 방문해 검사한 뒤 합격·불합격을 판정합니다. 합격하면 이관이 끝납니다.
이 신청 → 검토 → 방문 → 판정 → 통보의 한 사이클을 관리하는 시스템입니다.

---

## 등장 인물

| 용어 | 뜻 |
| --- | --- |
| **이관검사 신청자** | 장비를 설치한 **설치점**의 담당자. 신청서를 쓰고 보완요청에 대응합니다. 코드에서는 `applicant` |
| **감독관** | 검사를 수행하고 판정하는 사람. 방문예정일을 잡고 합격·불합격을 정합니다. 코드에서는 `supervisor` |
| **설치점** | 실제 시공·설치를 한 협력사 (예: `세움테크`). `applications.installer` |
| **원청** | 공사를 발주한 건설사 (예: `대림건설`). `applications.owner` |
| **현장PM** | 원청 측 현장 관리자. `applications.pm` |
| **입회자** | 감독관 방문 때 현장에서 함께 확인하는 사람. `applications.witness` |

> 한 계정은 역할 하나만 가집니다. 상단바의 역할 탭은 **현재 계정이 어느 쪽인지
> 보여 줄 뿐**이고, 눌러서 전환되지 않습니다 (권한 안내 토스트만 뜹니다).

## 핵심 용어

### 이관검사

준공된 현장의 장비를 발주처로 **이관(引渡)** 하기 전에 하는 검사입니다.
장비가 제대로 설치·동작하는지 확인하고, 하자가 있으면 보수를 요구합니다.

검사는 두 종류입니다.

| 종류 | 뜻 |
| --- | --- |
| **서류검사** | 제출 서류만으로 판정. 현장 방문 없이 처리 |
| **샘플링검사** | 현장을 방문해 일부 세대를 표본으로 확인 |

DB enum: `DOCUMENT` / `SAMPLING`

### 판정은 2단계

```
   현장 방문
       │
       ▼
   1차 판정  ──► 조건부합격 등으로 남겨 두고 재시공을 기다릴 수 있음
       │           (status = 최종판정대기)
       ▼
   최종 판정 ──► 확정. 신청자·현장PM·설치점 3곳에 통보되고 되돌릴 수 없음
```

1차만 먼저 기록하고 나중에 최종을 확정할 수 있습니다
(판정 화면의 **1차만 저장** 버튼). 1차를 건너뛰고 최종만 확정해도 되며,
그럴 때 이력에 `(1차 판정 없이 확정)` 이라고 남습니다.

> **하지 않은 1차 판정을 지어내지 않습니다.** 예전에는 최종만 입력하면
> 1차에 같은 값을 채워 넣어 이력이 "1차 합격 → 최종 합격" 으로 보였는데,
> 실제로는 1차를 한 적이 없었습니다. 지금은 채우지 않습니다.

### 판정 결과 5가지

| 결과 | 뜻 |
| --- | --- |
| **합격** | 이관 완료 |
| **조건부합격** | 지적 사항 조치를 조건으로 합격 |
| **불합격** | 재시공 후 다시 신청해야 함 |
| **보류** | 판정을 미룸. 차월 재검사 대상 |
| **이월** | 차년도로 넘김 |

DB enum: `PASS` / `CONDITIONAL` / `FAIL` / `HOLD` / `CARRY_OVER`

### 하자이행증권

**이 시스템에서 가장 중요한 업무 규칙이 걸려 있는 값입니다.**

설치점이 하자보증기간 동안 하자가 생기면 고쳐 주겠다는 약속을,
**보증기관이 대신 담보해 주는 증서**입니다. 설치점이 폐업하거나 이행을 거부해도
발주처가 보수 비용을 회수할 수 있게 하는 안전장치입니다.

실제 데이터의 발행기관: 건설공제회, 종합보증보험, 이행보증보험,
소프트웨어공제회, 산업공제조합, 통신공제조합.

| 값 | 컬럼 | 예 |
| --- | --- | --- |
| 하자이행증권 번호 | `bondNo` | `제000-000-2026 0000 0002호` |
| 발행기관 | `issuer` | `종합보증보험` · 없으면 `미발행` |
| 하자보증기간 개월 | `months` | 36 |
| 하자보증기간 시작·종료 | `bondFrom` / `bondTo` | |

**규칙: 하자이행증권이 확인되지 않으면 합격·조건부합격으로 확정할 수 없습니다.**

증권 없이 합격시키면 이관은 끝났는데 하자 담보 수단이 없는 상태가 되기 때문입니다.
불합격·보류·이월은 증권과 무관하게 확정할 수 있습니다 (담보가 필요 없으므로).

```
  issuer === '미발행'
  또는 bondNo 가 '입력 요망' / '추후발행' / 빈 값
        │
        ▼
  합격·조건부합격 칩이 화면에서 비활성 (누를 수 없음)
        │
        ▼
  화면을 우회해 요청을 보내도 서버가 거부
  → "하자이행증권이 확인되지 않아 합격 처리할 수 없습니다"
```

감독관 화면의 **하자이행증권 · 하자보증기간 확인** 체크박스는 감독관의
자기 확인 표시일 뿐입니다. 체크했다고 통과되지 않고, **서버가 실제
`issuer`/`bondNo` 값을 봅니다.**

### 하자보증기간

준공 후 설치점이 하자 보수 책임을 지는 기간입니다. 기본 36개월.
입주개시일을 기준으로 계산합니다. 이 기간 안에 이관검사를 신청해야 합니다.

## 상태 11가지

신청 한 건이 가질 수 있는 상태입니다. 화면 분기·권한·집계가 전부 이 값에 걸립니다.

| 상태 | DB enum | 지금 누구를 기다리는가 |
| --- | --- | --- |
| 작성중 | `DRAFT` | (현재 화면에서는 만들지 않음) |
| **신청완료** | `SUBMITTED` | 감독관의 검토 |
| **검토예정** | `REVIEW_PLANNED` | 감독관의 검토승인 (방문예정일은 잡힘) |
| **검토승인** | `REVIEW_APPROVED` | 감독관의 현장 방문 |
| **보완요청** | `FIX_REQUESTED` | **신청자의 수정·재신청** |
| **최종판정대기** | `FINAL_PENDING` | 감독관의 최종 판정 (1차는 끝남) |
| 최종합격 | `PASSED` | — 종료 |
| 조건부합격 | `CONDITIONAL` | — 종료 |
| 불합격 | `FAILED` | — 종료 |
| 보류 | `HOLD` | — 종료 |
| 이월 | `CARRIED_OVER` | — 종료 |

각 상태의 한 줄 설명은 `src/lib/domain.ts` 의 `STATUS_NOTE` 에 있고,
화면에서 상태 배지의 툴팁으로 나옵니다.

> **검토예정과 검토승인의 차이** — 둘 다 방문예정일이 있지만, 검토예정은
> 감독관이 날짜만 잡아 둔 상태이고, 검토승인은 서류 검토가 끝나 방문이
> 확정된 상태입니다. 신청자에게 통보가 나가는 것은 검토승인입니다.

상태 전이 그림은 [`docs/db-schema.md` §3](db-schema.md#3-상태status--이-시스템의-중심) 참조.

## 제품군

| 코드 | 뜻 | 양식 항목 수 |
| --- | --- | --- |
| **DDL** | 도어록 (Digital Door Lock) | 41개 |
| **HN / HA** | 홈네트워크 · 홈오토메이션 | 58개 |

제품군에 따라 신청서 항목이 완전히 다릅니다. 그래서 신규 신청은
**제품군을 먼저 고르고** 그에 맞는 폼이 뜹니다.

자주 쓰는 항목만 컬럼이고 나머지는 `applications.extra` (JSON) 에 들어갑니다.

| **직판** (`DIRECT`) | 제조사가 현장에 직접 납품 |
| **유통** (`DISTRIBUTION`) | 대리점을 거쳐 납품 |

## 화면에서 쓰는 말

| 말 | 뜻 |
| --- | --- |
| **식별번호** | 신청 건 번호. 화면·URL·엑셀에 그대로 쓰이는 업무 키 (예: `20260701`) |
| **방문예정일** | 감독관이 현장에 가기로 한 날. 캘린더·D-day·동선의 기준 |
| **동선** | 하루에 여러 현장을 도는 감독관의 방문 순서. `external_visits` 를 겹쳐 계산 |
| **입주개시일** | 입주가 시작된 달 (`'YYYY.MM'`). 하자보증기간 계산 기준 |
| **입주율 · 시공률** | 검사 시점의 진척도. 신청자가 적어 냅니다 (`occupancy`) |
| **보완요청** | 감독관이 신청을 반려하고 수정을 요구하는 것. 되돌아갈 수 있는 유일한 경로 |
| **재신청** | 신청자가 보완요청에 대응해 다시 제출하는 것 |
| **일괄 승인** | 목록에서 여러 건을 골라 한 번에 검토승인하는 것 |
| **처리 로그** | 누가·언제·무엇을 했는지의 이력. 신청자 화면에도 그대로 보입니다 |
| **통보 이력** | 이메일·문자를 보냈다는 기록 (실제 발송은 하지 않습니다) |

## 표기 규칙

문서·화면·코드에서 아래 표기를 씁니다. 줄여 쓰지 않습니다.

| 쓸 것 | 쓰지 말 것 |
| --- | --- |
| 하자이행증권 | 증권 |
| 하자이행증권 번호 | 증권번호 |
| 하자보증기간 | 보증기간 |
| 합격·불합격 | 합·불, 합불 |
| 연도 · 연도별 | 년도, 년도별 (두음법칙) |
| 입주개시일 | 입주개시 |
| 이관검사 신청자 | 신청자 (문맥이 분명하면 허용) |

DB 컬럼명은 짧은 영문(`bondNo`, `issuer`)을 유지합니다 — 화면 표기와 별개입니다.

## 코드에서 용어가 사는 곳

```
  src/lib/domain.ts     한글 라벨 ↔ DB enum 변환표, 상태 설명, 배지 색
  src/lib/view.ts       화면 파생 로직 (배지 · 타임라인 · KPI · 동선)
  src/lib/actions.ts    상태를 바꾸는 모든 동작 + 업무 규칙 검증
  prisma/schema.prisma  저장 구조
```

**용어를 바꾸려면 `src/lib/domain.ts` 부터 보세요.** 변환표가
`satisfies Record<StatusLabel, string>` 로 묶여 있어, 한쪽만 바꾸면
`npx tsc --noEmit` 이 잡아 줍니다.
